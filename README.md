# Tabletop RPG Engine

A single-player tabletop role-playing game engine. Game mechanics are resolved deterministically in
Python; narration is optionally generated by a large language model (LLM).

## Overview

The engine is independent of any particular game system. Game systems are implemented as
**rulesets** that conform to a common interface. Two rulesets are included:

| Ruleset | Version | Scope |
|---------|---------|-------|
| D&D (d20) | 1.11.0 | 9 races, 12 classes (levels 1–20), backgrounds, alignments, proficiencies, spells, equipment, trade, exploration scenes. Includes two Forgotten Realms adventures: *The Watcher's Barrow* and *Out of the Abyss*, Chapter 1. |
| Storyteller (Vampire: The Masquerade) | 1.0.0 | d10 dice pools, Blood, Humanity, frenzy, 15 Disciplines and paths (75 powers), Thaumaturgy and Necromancy rituals. |

Two front-ends are provided: a command-line interface (CLI) and a local web interface. Both use the
same engine through a shared event interface.

## Design principles

The architecture is governed by two invariants:

1. **All numeric values are computed in Python.** Dice pools, damage, difficulty classes and
   effects are never produced by the language model. The model performs exactly two tasks:
   classifying player intent into a grammar-constrained closed set, and narrating outcomes from
   qualitative cues. Rolls and difficulty values are never included in its prompts.
2. **Mechanical results are expressed as qualitative status tokens** (for example, `hidden`,
   `terrified`, `dominated`). A new power is defined by data and a single resolver function; it
   requires no changes to the engine's control flow.

## Requirements

| Component | Requirement |
|-----------|-------------|
| Python | 3.10 or later; developed and tested on 3.14. |
| Dependencies | None. Only the Python standard library is used. |
| Operating system | Any. The `launch.bat` launcher is Windows-only. |
| Language model | Optional. A llama.cpp `llama-server` instance with a GGUF model, or any OpenAI-compatible API. If no model is configured, a built-in canned narrator is used. |

## Quick start

All commands are executed from the `tabletop-rpg-engine/` directory.

```sh
git clone https://github.com/Demetrius242/tabletop-rpg-engine.git
cd vtm_rpg_engine/core
```

| Command | Result |
|---------|--------|
| `python run_web.py` | Starts the web interface at `http://127.0.0.1:8765/`. |
| `python run.py` | Starts the CLI. |
| `python run.py --fake` | Starts the CLI with the canned narrator; no model is required. |
| `launch.bat` | Windows only. Starts the local model, if present, and the web interface. Falls back to the CLI if the web server cannot start. |

## Language model configuration

A language model is required only for generated narration. The following backends are supported:

| Backend | Configuration | Notes |
|---------|---------------|-------|
| llama.cpp | Place a `.gguf` file in `tabletop-rpg-engine/llm/models/` and `llama-server.exe` in `tabletop-rpg-engine/llm/` or on `PATH`, then run `launch.bat`. | The only backend that supports GBNF grammar-constrained intent classification. |
| OpenAI-compatible API | Set the endpoint under **Model connection** in the web interface, or pass `--server` and `--openai` to `run.py`. | Compatible with KoboldCpp, oobabooga, LM Studio, vLLM, TabbyAPI and hosted providers. |

Prompts are formatted with the ChatML chat template; the selected model must support it. Detailed
setup instructions are provided in [tabletop-rpg-engine/llm/README.md](tabletop-rpg-engine/llm/README.md).

## Repository structure

```
vtm_rpg_engine/
├─ tabletop-rpg-engine/                  game engine, rulesets and front-ends
 ├─ engine/             system-agnostic core: turn pipeline, dice, combat, zones,
 │                      story state machine, LLM clients, add-on loader
 ├─ rulesets/
 │  ├─ dnd/             D&D ruleset
 │  └─ storyteller/     Vampire: The Masquerade ruleset
 ├─ web/                web interface: HTTP and WebSocket server, static front-end
 ├─ data/               authored content in JSON: NPCs, locations, saves
 ├─ docs/               user and developer documentation
 ├─ llm/                local model binaries and GGUF files (not included)
 ├─ run.py              CLI entry point
 └─ run_web.py          web interface entry point

```

## Testing

No test framework is used. Each test suite is a standalone script that reports the number of passed
checks and exits with a non-zero status on failure. Suites use a fake LLM client and scripted dice;
results are deterministic and no model is required.

```sh
cd core
python engine/tests/test_engine.py
python rulesets/dnd/tests/test_combat.py
python web/tests/test_web.py
```

Every `tests/test_*.py` file under `tabletop-rpg-engine/engine/`, `tabletop-rpg-engine/rulesets/` and `tabletop-rpg-engine/web/` is a test
suite. Add-ons provide their own suites in `<add-on>/tests/`.

Each ruleset additionally provides a readiness probe that validates it against the engine contract.
The probe exits with status 0 if the ruleset is complete and 1 otherwise:

```sh
python rulesets/dnd/readiness.py
python rulesets/storyteller/readiness.py
```

## Extensibility

| Extension point | Mechanism |
|-----------------|-----------|
| Content | NPCs, locations, plots and scenes are defined in JSON files. No source code changes are required. |
| Rulesets | A new game system is implemented as a subclass of `Ruleset` (`tabletop-rpg-engine/engine/ruleset.py`). |
| Add-ons | A self-contained directory placed alongside `tabletop-rpg-engine/`, containing an `addon.json` manifest and an `install()` function. Add-ons integrate exclusively through generic hooks; the core contains no references to specific add-ons. Deleting the directory removes the add-on completely. |
